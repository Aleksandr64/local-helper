# Тул для local_helper: новий або підключений

Правила проєкту — у `CLAUDE.md`, повний контракт тулу — у `GUIDE.md` (розділи «Контракт тулу» і
«Тули на PowerShell і Bash»). Тут — порядок дій. Команди виконуй з кореня репозиторію
Python'ом з `.venv`: `.\.venv\Scripts\python.exe local_helper.py <команда>` (далі — `lh`).

## 1. Що саме просять

- **Новий тул** → крок 2.
- **Існуючий скрипт** (дали шлях до файлу чи папки) → крок 3.
- **«Щоб запускався в папці X»** → лише крок 4 для вже існуючого тулу.

Групу бери з `lh groups`; нову групу створюй, тільки якщо жодна не підходить або попросили.

## 2. Новий тул

Мова:
- **py** — за замовчуванням: обробка файлів, парсинг, конвертації;
- **ps1** — коли просять PowerShell або задача суто Windows-на (служби, реєстр, планувальник,
  COM/Office, `Get-*`-командлети);
- **sh** — лише коли просять Bash або є готові bash-команди. Потрібен Git Bash.

```powershell
lh new <name> --lang py|ps1|sh --group <група> --description "Короткий опис"
```

Допиши логіку в `tools/<name>/main.<ext>` за контрактом відповідної мови (нижче). Python-залежності —
у `tools/<name>/requirements.txt` і `lh setup`. Новий вбудований тул — додай рядок у таблицю «Тули»
в `README.md`.

## 3. Підключити існуючий скрипт

1. **Прочитай скрипт повністю.** Зрозумій, що він робить, які приймає аргументи, що змінює.
2. **Допиши опис у сам файл** (користувач погодився, що опис живе в скрипті):
   - `.py` — docstring на самому початку: перший рядок — коротко, далі деталі й 1–3 приклади
     `local_helper <name> ...`;
   - `.ps1` — comment-based help першим блоком: `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER` для
     кожного параметра, `.EXAMPLE`;
   - `.sh` — після shebang суцільний блок `#`-коментарів: перший рядок — коротко, далі параметри
     й приклади.
   Існуючий опис доповнюй, а не переписуй.
3. **Параметри — у форму, яку розуміє лаунчер**, якщо скрипт бере їх інакше:
   - `.py` — `argparse` (інакше в TUI не буде форми), до `parse_args()` нічого важкого;
   - `.ps1` — блок `param()`: `[switch]` для прапорців, `[ValidateSet()]` для варіантів,
     `[Parameter(Mandatory)]` для обов'язкових;
   - `.sh` — розбір `$1…`/`while case`; форми в TUI не буде, аргументи вводяться рядком.
   Інтерактивний ввід (`input()`, `Read-Host`, `read`) заміни параметрами: у TUI stdin закритий.
   **Логіку скрипта не змінюй** без прохання; якщо без цього не обійтись — спершу спитай.
   Якщо скрипт лежить у чужому git-репозиторії чи використовується ще кимось — попередь про зміни.
4. **Підключи:**
   ```powershell
   lh add "<шлях до файлу або папки>" --group <група> [--name <ім'я>] [--workdir "<папка>"]
   ```
   Ім'я — `snake_case`; якщо назва файлу з кирилицею чи зайнята — задай `--name`.
   У папці кілька скриптів — `--entry <файл>`.

## 4. Робоча папка

Якщо тул має завжди працювати в певній папці (проєкт, архів, папка з даними):
```powershell
lh workdir <name> "<папка>"      # показати: lh workdir <name>; прибрати: --clear
```
Відносні шляхи в аргументах тоді рахуються від цієї папки.

## 5. Перевірка (обов'язково)

1. `lh list` — тул є, опис нормальний, тег `[ps1]`/`[sh]`/`[папка]` де треба.
2. `lh <name> -help` — опис і параметри (для `.ps1` — таблиця з `param()`).
3. Реальний запуск на тестових даних у scratch-/тимчасовій папці, не в репозиторії; для тулів,
   що змінюють файли, — спершу `--dry-run` / `-DryRun`.
4. Помилковий вхід (неіснуючий шлях) — зрозуміле повідомлення в stderr і код ≠ 0.
5. Змінювався `local_helper.py` — `.\.venv\Scripts\python.exe -m unittest discover tests`.

Наприкінці коротко скажи, як запускати тул (`lh <name> ...`) і в якій він групі.

## Контракт .ps1

```powershell
<#
.SYNOPSIS
    Чистить старі файли в папці.
.DESCRIPTION
    Видаляє файли, старші за -Days днів. Без -Force лише показує, що видалить.
.PARAMETER Path
    папка
.PARAMETER Days
    вік файлів у днях
.EXAMPLE
    local_helper clean_old -Path D:\Temp -Days 30
#>
param(
    [Parameter(Mandatory)][string]$Path,
    [int]$Days = 30,
    [ValidateSet("all", "logs")][string]$Kind = "all",
    [switch]$DryRun
)
$ErrorActionPreference = "Stop"
[Console]::OutputEncoding = [Text.Encoding]::UTF8
if (-not (Test-Path -LiteralPath $Path)) {
    [Console]::Error.WriteLine("Папку не знайдено: $Path")
    exit 1
}
# ...
exit 0
```

- Файл у UTF-8 **з BOM** (`lh new` так і створює): інакше Windows PowerShell 5.1 ламає кирилицю.
- Лаунчер запускає `pwsh -NoProfile -ExecutionPolicy Bypass -File`: масиви (`[string[]]`) з командного
  рядка не розбиваються — бери рядок і розбивай сам (`-split ','`). Замість `[bool]` — `[switch]`.
- Помилки — `[Console]::Error.WriteLine(...)` + `exit 1`, без червоних traceback'ів `Write-Error`.
- Шляхи — `-LiteralPath` (квадратні дужки в іменах файлів).

## Контракт .sh

```bash
#!/usr/bin/env bash
# Стискає логи старші за N днів.
#
# Параметри:
#   [папка]     де шукати (за замовчуванням — поточна)
#   --days N    вік у днях (30)
#   --dry-run   лише показати
#
# Приклад:
#   local_helper gzip_logs /d/logs --days 7
set -euo pipefail
```

- Тільки LF-кінці рядків (`.gitattributes` це гарантує для репозиторію; для зовнішніх файлів перевір).
- Запускається Git Bash'ем: Windows-шляхи в аргументах доходять як є (`D:\Logs`), бажано
  обробляти через `cygpath -u`, якщо потрібні POSIX-шляхи.
- Помилки — `echo ... >&2; exit 1`.
