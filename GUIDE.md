`local_helper` (коротко `lh`) — це особистий набір консольних тулів (на Python, PowerShell або Bash)
і лаунчер, через який вони запускаються: з командного рядка або в повноекранному інтерфейсі в терміналі.

## 1. Встановлення

**Потрібно:** Windows 10/11, Python 3.10+ з галочкою «Add to PATH», PowerShell.
Перевірити, що Python є:
```powershell
python --version
```

**Кроки (один раз):**

1. Отримати папку з тулами: скопіювати її або клонувати репозиторій, наприклад у
   `D:\Dev\Diferrent Tools`.
2. Створити віртуальне середовище й встановити залежності (Textual для інтерфейсу і пакети тулів):
   ```powershell
   python "D:\Dev\Diferrent Tools\local_helper.py" setup
   ```
3. Додати папку в PATH користувача, щоб команди `lh` і `local_helper` працювали з будь-якого місця:
   ```powershell
   powershell -ExecutionPolicy Bypass -File "D:\Dev\Diferrent Tools\install.ps1"
   ```
4. **Закрити й знову відкрити термінал.** Старі вікна нового PATH не бачать.
5. Перевірити:
   ```powershell
   lh list
   ```

Команда пишеться як `local_helper` (з підкресленням) або `lh`. Варіант `localhelper` без
підкреслення не працює.

**У Git Bash** команда теж `lh`: для нього в корені лежить bash-обгортка `lh` без розширення
(PowerShell і cmd її не бачать і беруть `lh.cmd`). `local_helper` у Git Bash — лише як `local_helper.cmd`.

**Що саме «встановлюється».** Це не програма з інсталятором: нічого не копіюється в
`Program Files`, немає запису в «Програми та компоненти» чи реєстрі. Уся CLI живе в цій папці, а
встановлення — це дві речі: `.venv` усередині папки (`lh setup`) і шлях до папки в змінній `Path`
користувача (`install.ps1`), завдяки якому `lh.cmd` знаходиться з будь-якого терміналу. Тому
оновлення — це `git pull`, а «видалення» — прибрати папку з `Path` і видалити саму папку.

## 2. Запуск і користування

### Графічний інтерфейс у терміналі

```powershell
lh
```

Відкривається повноекранний інтерфейс:
- **зліва** — дерево тулів по групах і пошук (за назвою, описом і групою); підключені з інших
  папок позначені `added`, тули на PowerShell і Bash — `ps1` і `sh`;
- **справа** — опис вибраного тулу і **форма параметрів**, яку інтерфейс будує сам з argparse
  (Python) або `param()` (PowerShell): прапорці стають галочками, варіанти (`choices`,
  `ValidateSet`) — списками, решта — полями вводу, обов'язкові параметри позначені `*`;
  якщо за тулом закріплена робоча папка, вона показана під назвою;
- рядок `▶ lh …` показує команду, яка буде виконана;
- **знизу** — вивід тулу в реальному часі і код виходу.

| Клавіша | Дія |
|---|---|
| `↑` `↓`, мишка | вибрати тул; `Enter` — перейти до форми (на групі — згорнути/розгорнути) |
| `Ctrl+R` / `Ctrl+S` | запустити / зупинити тул |
| `/` | пошук за назвою й описом |
| `Ctrl+W` | змінити робочу папку (від неї рахуються відносні шляхи) |
| `w` | закріпити за вибраним тулом папку, в якій він завжди запускається (або прибрати) |
| `n` | створити новий тул: ім'я, опис, мова (Python / PowerShell / Bash), група |
| `g` | змінити групу вибраного тулу або прибрати його з групи |
| `a` / `d` | підключити тул з іншої папки / відключити підключений |
| `r` | перечитати список тулів (після змін у файлах) |
| `Ctrl+P` | палітра команд, зокрема світла чи темна тема |
| `q` | вихід |

Робоча папка за замовчуванням — та, з якої запущено `lh`. Тул із закріпленою папкою (`w`)
завжди запускається в ній, незалежно від `Ctrl+W`.

### Командний рядок

| Команда | Що робить |
|---|---|
| `lh` або `lh ui` | графічний інтерфейс |
| `lh list [група]` | список тулів по групах з коротким описом; з назвою групи — лише її тули |
| `lh <tool> -help` | що робить тул і які параметри приймає (також `--help`, `-h`, `help`, `?`) |
| `lh <tool> [параметри]` | запустити тул у поточній папці терміналу (або в закріпленій за ним) |
| `lh new <name> [--lang py\|ps1\|sh] [--description D] [--group G] [--workdir P]` | створити новий тул за шаблоном |
| `lh add <шлях> [--name N] [--entry файл] [--group G] [--workdir P]` | підключити тул з будь-якої папки |
| `lh workdir <tool> [папка \| --clear]` | закріпити за тулом папку запуску / показати / прибрати |
| `lh group <tool> <група>` / `lh ungroup <tool>` | покласти тул у групу / прибрати з групи |
| `lh groups` | усі групи і тули в них (`groups rename …`, `groups delete …`) |
| `lh remove <tool>` | відключити підключений тул (файли не видаляються) |
| `lh setup` | створити `.venv` і встановити всі `requirements.txt` |

Приклади:
```powershell
lh photos_to_pdf -help
lh photos_to_pdf "D:\Scans\Паспорт" --dry-run
lh photos_to_pdf "D:\Scans\Паспорт" --sort date
lh count_lines . --ext .py .md
```

Якщо назву тулу написано з помилкою, `lh` підкаже схожі. Тул повертає свій exit code, тож
`lh` можна використовувати в скриптах.

## 3. Створення нових тулів через Claude

Найшвидший спосіб — попросити Claude Code. Для цього в проєкті є скіл `/lh-tool`
([.claude/skills/lh-tool/SKILL.md](.claude/skills/lh-tool/SKILL.md)): Claude бере його сам, коли
просиш створити тул або підключити скрипт, а можна й викликати явно: `/lh-tool підключи D:\Scripts\backup.ps1`.

1. Відкрий Claude Code у папці `D:\Dev\Diferrent Tools` (в Claude desktop — вкладка Code, папка
   проєкту; або `claude` у терміналі в цій папці). Файл [CLAUDE.md](CLAUDE.md) підвантажиться
   автоматично: там правила, за якими Claude пише тули.
2. Опиши задачу людською мовою: що тул отримує на вхід, що робить, що видає. Приклади запитів:
   - «Створи тул, який перейменовує фото в папці за датою зйомки у формат 2024-05-01_001.jpg»
   - «Зроби тул: стиснути всі відео в папці до 720p через ffmpeg, з --dry-run»
   - «Тул, який з Excel-файлу робить CSV для кожного аркуша»
   - «Додай у photos_to_pdf параметр --quality для стиснення JPEG»
   - «Зроби на PowerShell тул, який показує, які процеси тримають файл»
3. Claude:
   - створить `tools/<name>/main.py` (і `requirements.txt`, якщо потрібні пакети);
   - напише docstring з прикладами і параметри через argparse;
   - встановить залежності (`lh setup`) і перевірить тул на тестових даних;
   - для нетривіальної логіки додасть тести в `tests/test_<name>.py`.
4. Тул одразу з'явиться в `lh list` і в інтерфейсі (`r`, якщо інтерфейс уже відкритий).

**Що варто сказати Claude, щоб вийшло з першого разу:**
- приклад вхідних даних і бажаного результату;
- чи змінює тул файли (тоді буде `--dry-run` і `--force`);
- де за замовчуванням зберігати результат;
- чи можна ставити сторонні пакети, чи тільки стандартна бібліотека.

**Існуючий скрипт** (`.py`, `.ps1` або `.sh`) теж можна віддати Claude: «підключи
D:\Scripts\backup.ps1 у lh, група Утиліти, запускати в D:\Data». Claude:
- прочитає скрипт і **допише опис у сам файл** (docstring, comment-based help або `#`-коментар з
  прикладами), не змінюючи логіку;
- за потреби переведе параметри на argparse / `param()` і прибере інтерактивний ввід, щоб працювали
  `-help` і форма в інтерфейсі (зміни логіки — лише з твого дозволу);
- виконає `lh add … --group …` і, якщо треба, `lh workdir`, а потім перевірить `-help` і запуск.

## 4. Створення тулу вручну

1. Створи заготовку з терміналу:

   Або в інтерфейсі: `n`, далі ім'я й опис.

`ungroup`, `groups`, `workdir`.

## 5. Контракт тулу: що має бути в main.py

Лаунчер знаходить тул за шляхом `tools/<name>/main.py` (або `main.ps1`, `main.sh` — див.
[розділ 6](#6-тули-на-powershell-і-bash)). Папки, назва яких починається з `_` чи `.`,
ігноруються, тож у них можна тримати чернетки або спільний код.

```python
"""Перейменовує фото в папці за датою зйомки.

Імена стають такими: 2024-05-01_001.jpg. Дата береться з EXIF, а якщо її немає — з дати файлу.

Приклади:
    local_helper rename_photos D:\\Photos --dry-run
    local_helper rename_photos . --prefix trip
"""
import argparse
import sys
from pathlib import Path


def main() -> int:
    parser = argparse.ArgumentParser(
        prog="local_helper rename_photos",
        description=__doc__,
        formatter_class=argparse.RawDescriptionHelpFormatter,
    )
    parser.add_argument("folder", type=Path, nargs="?", default=Path("."), help="папка з фото")
    parser.add_argument("--prefix", default="", help="префікс до імені")
    parser.add_argument("--dry-run", action="store_true", help="лише показати, що буде зроблено")
    parser.add_argument("--force", action="store_true", help="перезаписувати існуючі файли")
    args = parser.parse_args()

    if not args.folder.is_dir():
        print(f"Папку не знайдено: {args.folder}", file=sys.stderr)
        return 1
    ...
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Правила:

| Що | Навіщо |
|---|---|
| **Docstring на самому початку файлу.** Перший рядок — короткий опис, далі деталі й приклади | перший рядок показується в `lh list`, весь docstring — у `-help` та інтерфейсі |
| **Параметри через `argparse`** з `prog="local_helper <name>"`, `description=__doc__`, `help=` у кожного аргументу | з цього будується `-help` і форма в інтерфейсі |
| **До `parse_args()` — лише імпорти, константи і створення парсера** | щоб зібрати форму, інтерфейс запускає скрипт до `parse_args()` |
| **Без `input()`** | в інтерфейсі stdin закритий: усе має передаватися параметрами |
| `main() -> int` і `sys.exit(main())` | коректний exit code, тул можна запустити і без лаунчера |
| Шляхи через `pathlib.Path`, файли з `encoding="utf-8"` | пробіли й кирилиця в шляхах |
| Відносні шляхи — від поточної папки користувача | тул запускається в робочій папці терміналу чи інтерфейсу |
| Тули, що змінюють файли, мають `--dry-run` і не перезаписують без `--force` | безпечність за замовчуванням |
| Помилки — коротке повідомлення в stderr і код ≠ 0, без traceback | в інтерфейсі вони показуються червоним |
| Спочатку стандартна бібліотека; пакети — в `tools/<name>/requirements.txt` | менше залежностей, `lh setup` ставить усе разом |
| Тули не імпортують один одного | кожен тул самодостатній |

**Чекліст «тул готовий»:**
- [ ] `lh list` показує тул з нормальним описом
- [ ] `lh <name> -help` показує опис і всі параметри з поясненнями
- [ ] в інтерфейсі будується форма, а запуск з неї працює
- [ ] реальний запуск на тестових даних дає очікуваний результат
- [ ] `--dry-run` нічого не змінює (якщо тул змінює файли)
- [ ] помилкові вхідні дані дають зрозуміле повідомлення, а не traceback

## 6. Тули на PowerShell і Bash

Крім Python, тул може бути скриптом PowerShell (`.ps1`) або Bash (`.sh`). Лаунчер запускає їх так:

| Тип | Команда запуску | Опис для `list` / `-help` | Форма в інтерфейсі |
|---|---|---|---|
| `.py` | Python з `.venv` | docstring | з `argparse` |
| `.ps1` | `pwsh -NoProfile -ExecutionPolicy Bypass -File` (якщо `pwsh` немає — `powershell`) | comment-based help `<# .SYNOPSIS … #>` | з `param()` |
| `.sh` | Git Bash (`C:\Program Files\Git\bin\bash.exe`) | `#`-коментар після shebang | немає, аргументи рядком |

Вбудований тул — `tools/<name>/main.ps1` чи `main.sh`; створити заготовку: `lh new <name> --lang ps1`
або `--lang sh`. Підключити зовнішній: `lh add D:\Scripts\backup.ps1`.

### PowerShell

```powershell
<#
.SYNOPSIS
    Чистить старі файли в папці.

.DESCRIPTION
    Видаляє файли, старші за -Days днів. З -DryRun лише показує, що видалить.

.PARAMETER Path
    папка

.PARAMETER Days
    вік файлів у днях

.EXAMPLE
    local_helper clean_old -Path D:\Temp -Days 30 -DryRun
#>
param(
    [Parameter(Mandatory)][string]$Path,
    [int]$Days = 30,
    [ValidateSet("all", "logs")][string]$Kind = "all",
    [switch]$DryRun
)

$ErrorActionPreference = "Stop"
[Console]::OutputEncoding = [Text.Encoding]::UTF8

if (-not (Test-Path -LiteralPath $Path)) {
    [Console]::Error.WriteLine("Папку не знайдено: $Path")
    exit 1
}
# ...
exit 0
```

- `.SYNOPSIS` — опис у `lh list`; `.DESCRIPTION` і `.EXAMPLE` — у `-help`; `.PARAMETER` —
  пояснення поруч із полем форми.
- Форма будується з `param()` без запуску скрипта: `[switch]` → галочка, `[ValidateSet()]` → список,
  `[Parameter(Mandatory)]` → обов'язкове поле, значення за замовчуванням — підказка.
- Для прапорців бери `[switch]`, а не `[bool]`. Масиви (`[string[]]`) у режимі `-File` з командного
  рядка не розбиваються — приймай рядок і розбивай сам (`$Ext -split ','`).
- `[Console]::OutputEncoding = UTF8` — щоб кирилиця у виводі читалась в інтерфейсі.
- Файл зберігати в UTF-8 **з BOM** (`lh new` так і робить), інакше Windows PowerShell 5.1 ламає кирилицю.
- Без `Read-Host`: в інтерфейсі stdin закритий.

### Bash

```bash
#!/usr/bin/env bash
# Стискає логи, старші за N днів.
#
# Параметри:
#   [папка]     де шукати (за замовчуванням — поточна)
#   --days N    вік у днях (30)
#   --dry-run   лише показати
#
# Приклад:
#   local_helper gzip_logs D:\Logs --days 7
set -euo pipefail
```

- Потрібен **Git Bash** ([git-scm.com](https://git-scm.com/download/win)). `C:\Windows\System32\bash.exe`
  (WSL) лаунчер не використовує.
- Опис — суцільний `#`-коментар одразу після shebang; перший рядок іде в `lh list`, весь блок — у `-help`.
- Форми параметрів немає: в інтерфейсі аргументи вводяться рядком у «Додаткові аргументи».
- Кінці рядків — лише LF (у репозиторії це забезпечує `.gitattributes`); з CRLF bash падає з `$'\r'`.
- Windows-шляхи в аргументах доходять як є (`D:\Logs`); якщо потрібен POSIX-шлях — `cygpath -u "$1"`.

Загальні правила з [розділу 5](#5-контракт-тулу-що-має-бути-в-mainpy) (опис з прикладами, без
інтерактиву, `--dry-run`/`-DryRun` і `--force`/`-Force`, помилки в stderr і код ≠ 0) діють і тут.

## 7. Підключення тулів з інших папок

Скрипт, що лежить деінде, можна не копіювати, а підключити:
```powershell
lh add "D:\Scripts\video_compress"
lh add .                                 # поточна папка
lh add "D:\Scripts\cleanup.py" --name cleanup
lh add "D:\Scripts\backup.ps1" --group Утиліти --workdir "D:\Data"
```

- Підключати можна `.py`, `.ps1` і `.sh`.
- **Головний файл** шукається так: `main.py` → `__main__.py` → `main.ps1` → `main.sh` → єдиний
  скрипт у папці. Якщо скриптів кілька, вкажи головний через `--entry`.
- **Ім'я** береться з назви папки чи файлу (`Video Compress` → `video_compress`). Якщо в назві є
  кирилиця або ім'я зайняте, задай своє: `--name`.
- Тул **лишається на місці**, CLI запам'ятовує шлях у `registry.json`. Зміни в скрипті
  підхоплюються одразу.
- **Python для запуску** (для `.py`): `.venv` у папці тулу, якщо він є; інакше `.venv` лаунчера. Якщо в тулу є
  `requirements.txt`, а власного `.venv` немає, його залежності встановить `lh setup`.
- `--workdir` одразу закріплює папку запуску (див. [розділ 9](#9-робоча-папка-тулу)).
- Відключити тул: `lh remove <name>` (файли не видаляються; група й робоча папка тулу забуваються).
- Якщо папку перенесли, `lh list` покаже `[не знайдено]`; тоді треба виконати `lh remove`
  і знову `lh add` з новим шляхом.

`registry.json` не зберігається в git, бо шляхи прив'язані до конкретного ПК.

## 8. Групи тулів

Коли тулів багато, їх можна розкласти по групах: «Фото», «Документи», «Відео» тощо.
Групи запам'ятовуються у файлі `groups.json` і зберігаються в git разом із тулами.

```powershell
lh group photos_to_pdf Фото           # покласти тул у групу; група створюється сама
lh group count_lines "Файли і текст"  # назва може бути з пробілами й кирилицею
lh ungroup count_lines                # прибрати тул з групи
lh groups                             # усі групи і тули в них
lh list Фото                          # тули однієї групи
lh groups rename Фото "Фото й скани"  # перейменувати групу
lh groups delete Фото                 # видалити групу (тули лишаються, просто без групи)
lh new rename_photos --group Фото     # новий тул одразу в групі
lh add "D:\Scripts\my_tool" --group Утиліти
```

- У кожного тулу може бути одна група. Тули без групи потрапляють у розділ «Без групи».
- Регістр у назві групи не важливий: `фото` і `Фото` — одна група, лишається написання,
  з яким групу створили.
- Групи сортуються за алфавітом, «Без групи» завжди внизу. Поки немає жодної групи, список
  лишається плоским.
- В інтерфейсі групи показуються деревом, яке можна згортати. Клавіша `g` змінює групу
  вибраного тулу; поле підказує існуючі групи (`→` приймає підказку). У вікнах `n` і `a` теж
  можна одразу задати групу.
- Пошук в інтерфейсі шукає й за назвою групи: «фото» покаже всі тули групи «Фото».
- `lh remove` прибирає підключений тул і з групи.

## 9. Робоча папка тулу

Зазвичай тул запускається в поточній папці терміналу (в інтерфейсі — в робочій папці `Ctrl+W`).
Якщо тул завжди працює з однією папкою (проєкт, архів, папка з даними), її можна закріпити:

```powershell
lh workdir backup "D:\Data"     # тепер backup завжди запускається в D:\Data
lh workdir backup .              # поточна папка терміналу
lh workdir backup                # показати закріплену папку
lh workdir backup --clear        # знову запускати в поточній папці
lh new backup --lang ps1 --workdir "D:\Data"
lh add "D:\Scripts\sync.sh" --workdir "D:\Projects\site"
```

- Відносні шляхи в аргументах тулу рахуються від закріпленої папки.
- В інтерфейсі: клавіша `w` на вибраному тулі (кнопка «Прибрати» — скинути). Закріплена папка
  показана під назвою тулу, а рядок запуску в виводі — `(у <папка>)`.
- `lh list` позначає такі тули `[папка]`, `lh <tool> -help` показує саму папку.
- Якщо папку видалили чи перенесли, тул не запуститься й підкаже `lh workdir <tool> --clear`.
- Папки зберігаються у `workdirs.json` — не в git, бо шляхи прив'язані до конкретного ПК.

## 10. Перевстановлення, перенесення, проблеми

**Перевстановити залежності з нуля:**
```powershell
Remove-Item -Recurse -Force "D:\Dev\Diferrent Tools\.venv"
lh setup
```
Без `.venv` команда `lh` запускається звичайним Python, тому `lh setup` спрацює.

**Перенести папку в інше місце:** перенести, виконати `install.ps1` з нового місця, а старий
шлях прибрати з PATH вручну: Win → «Змінні середовища» → `Path` користувача.

| Проблема | Рішення |
|---|---|
| `lh: The term 'lh' is not recognized` | перевідкрий термінал; якщо не допомогло — запусти `install.ps1` |
| Замість інтерфейсу — текстове меню й «textual не встановлено» | `lh setup` |
| Тул пише «Не встановлено пакет …» | `lh setup` |
| Тулу немає в списку | перевір, що файл називається саме `tools/<name>/main.py`, а папка не починається з `_` чи `.`; в інтерфейсі натисни `r` |
| У формі інтерфейсу немає параметрів | тул не використовує argparse; аргументи можна ввести рядком у «Додаткові аргументи» |
| Тул «висить» в інтерфейсі | він чекає `input()`; зупини `Ctrl+S` і запускай з терміналу: `lh <tool> …` |
| Кракозябри замість кирилиці | лаунчер вмикає UTF-8 сам; при запуску напряму через `python main.py` виконай `$env:PYTHONUTF8=1`; у `.ps1` додай `[Console]::OutputEncoding = [Text.Encoding]::UTF8` і збережи файл з BOM |
| «Для .sh-тулів потрібен Git Bash» | встанови Git for Windows; WSL-овий `bash.exe` не підходить |
| «Для .ps1-тулів потрібен PowerShell» | встанови PowerShell 7 (`winget install Microsoft.PowerShell`) |
| `.sh`-тул падає з `$'\r': command not found` | у файлі CRLF; збережи з LF-кінцями рядків |
| «Робочу папку тулу … не знайдено» | `lh workdir <tool> <нова папка>` або `lh workdir <tool> --clear` |
| Аргумент з `%ІМ'Я%` (напр. папка `%PATH%`) приходить у тул розгорнутим | так робить cmd.exe з усіма `.cmd`-файлами, у тому числі `lh.cmd`; в PowerShell і cmd такий шлях через `lh` не передати — запусти `python "D:\Dev\Diferrent Tools\local_helper.py" …` або `lh` з Git Bash. Поодинокий `%` (`100%`), `&`, `!`, `^`, `$`, `'`, `[ ]` проходять нормально |
| `lh: command not found` у Git Bash | перевідкрий Git Bash після `install.ps1`; обгортка `lh` лежить у корені папки |

## 11. Структура репозиторію і тести

```
Diferrent Tools/
├── local_helper.py        # лаунчер і текстові команди (тільки стандартна бібліотека)
├── local_helper_tui.py    # графічний інтерфейс у терміналі (Textual)
├── local_helper.cmd       # обгортки для PATH; запускають Python з .venv, якщо він є
├── lh.cmd
├── lh                     # та сама обгортка для Git Bash
├── install.ps1            # додає папку в PATH користувача
├── requirements.txt       # залежності лаунчера (textual)
├── registry.json          # підключені тули (створюється автоматично, не в git)
├── groups.json            # групи тулів (створюється автоматично, в git)
├── workdirs.json          # закріплені папки запуску тулів (створюється автоматично, не в git)
├── GUIDE.md               # цей посібник
├── CLAUDE.md              # правила для Claude Code
├── .claude/skills/lh-tool/  # скіл Claude: створити тул / підключити скрипт
├── tests/                 # тести (unittest)
│   └── smoke/             # наскрізні перевірки з PowerShell і Git Bash
└── tools/
    ├── photos_to_pdf/     # фото з папки → один PDF
    └── count_lines/       # статистика файлів і рядків
```

Запустити тести:
```powershell
.\.venv\Scripts\python.exe -m unittest discover tests
```

**Наскрізна (smoke) перевірка** запускає справжній `lh` так, як із терміналу: створює тимчасові
папки з «незручними» назвами (пробіли, кирилиця, `[ ]`, `'`, `&`, `%`, `!`, `$`, `^`, `;`, емодзі),
підключає в кожній тули `.py`, `.ps1` і `.sh`, перевіряє `-help`, запуск у закріпленій папці,
передачу аргументу-шляху і `lh workdir`. Тимчасові тули `smoke_*` після себе відключає.
```powershell
pwsh -File tests\smoke\smoke.ps1            # через lh.cmd, як у PowerShell
pwsh -File tests\smoke\smoke.ps1 -Python    # напряму через Python, без cmd.exe
```
```bash
bash tests/smoke/smoke.sh                   # з Git Bash, через обгортку lh
```
